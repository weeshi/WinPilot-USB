02
القرار الأول

اختر رقم الإصدار ووحّده

يجب أن يكون الرقم الجديد أكبر، وأن يظهر بالقيمة نفسها في المشروعين والـ manifests والوثائق.

سيُستخدم فيv1.1.1
ملفا csproj1.1.1.0ملفا manifestنفس القيمةVERSION.txt1.1.1
لا تعِد استخدام رقم منشور.إذا كان الإصدار السابق معيبًا، أصلحه في PATCH جديد بدل تحريك tag قديم.
03
قبل البناء

نظّف نطاق الإصدار

راجع ما تغيّر، اكتب ملاحظات الإصدار، ولا تخلط ملفات المستخدم أو مخرجات البناء مع المصدر.

مراجعة Git
git status --short
git diff --check
git diff

لا تدخل في حزمة USB

.git.github.workbinobjrelease-local

هذه ملفات تطوير. الحزمة التشغيلية تحتاج التطبيق والمحدث والسكربتات والأصول فقط.

04
بوابة الجودة

ابنِ، اختبر، ثم أنشئ الحزمة

نجاح GitHub Actions لا يعوض اختبار الواجهة والمحدث على Windows.

A

البناء النظيف

ينتج التطبيق والمحدث في جذر المشروع.

.\scripts\Build-WinPilot.ps1 -Clean
B

الاختبارات

الاستبدال، الحفظ، rollback، الحماية، البحث والتصنيف.

powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\Test-Updater.ps1

& "$env:WINDIR\SysWOW64\WindowsPowerShell\v1.0\powershell.exe" -NoProfile -STA -ExecutionPolicy Bypass -File .\scripts\Test-Search.ps1
C

حزمة محلية

أنشئ ZIP والبصمة قبل النشر.

.\scripts\New-UpdatePackage.ps1
WinPilot-USB.exeالتطبيق الرئيسي
WinPilot-Updater.exeعامل الاستبدال
Update.zipالحزمة المنشورة
05
مسار اختياري

أضف البرامج دون إعادة توزيع كل Apps

اختر المثبتات الجديدة فقط باستخدام Id. تبقى ملفات المستخدم الحالية كما هي.

local-apps.jsonتعريف البرنامج
{
  "Id": "new-program-id",
  "Name": "Program name",
  "Pattern": "Program-Offline.exe",
  "Type": "exe",
  "SilentArgs": "/S",
  "SHA256": "..."
}
  1. ضع المثبتداخل Apps باسم ثابت.
  2. سجّل SHA-256حدّث manifest.
  3. اختبر الصامتعلى جهاز منفصل.
  4. أنشئ الحزمةمرّر Id إلى AppIds.
.\scripts\New-UpdatePackage.ps1 -AppIds "program-one","program-two"
تحديث برنامج موجوداستخدم اسم ملف ثابت ليستبدله المحدث، أو اجعل Pattern يطابق الملف الجديد وحده.
06
إلى القناة العامة

ارفع المصدر وأنشئ Release

الـ tag هو مفتاح Workflow. أنشئه فقط بعد نجاح الاختبارات.

1 · SOURCE

Commit وPush

git add <الملفات-المعدلة>
git commit -m "Release V1.1.1"
git push origin master
2 · TRIGGER

Tag الإصدار

git tag -a v1.1.1 -m "WinPilot USB V1.1.1"
git push origin v1.1.1
3 · OBSERVE

راقب Workflow

gh run list --repo weeshi/WinPilot-USB --workflow release.yml --limit 5
gh run watch RUN_ID --repo weeshi/WinPilot-USB --exit-status
عقد الإصدار

خمسة أسماء لا تتغير

Required assets
  • WinPilot-USB.exeتنزيل يدوي
  • WinPilot-Updater.exeترقية V1.0
  • WinPilot-USB-Update.zipالحزمة
  • WinPilot-USB-Update.sha256البصمة
  • SHA256SUMS.txtالسجل
استبدال ZIP الآلي بحزمة تحتوي برامجأمر متقدم

افحص الحزمة أولًا؛ --clobber يحذف الأصل القديم قبل رفع البديل.

gh release upload v1.1.1 .\release-local\WinPilot-USB-Update.zip .\release-local\WinPilot-USB-Update.sha256 --repo weeshi/WinPilot-USB --clobber

اختبار المستخدم

ابدأ من الإصدار السابق

  1. شغّل نسخة أقدم.
  2. اضغط Check updates.
  3. نزّل ووافق على إعادة التشغيل.
  4. تحقق من الرقم الجديد.
  5. تأكد من Apps وAds وinfo.txt.
